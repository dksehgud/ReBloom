## 2. 빌드 방법

### Backend

```bash
cd BE
./gradlew :services:<service-name>:bootJar -x test
```

빌드 대상 서비스:

```text
auth-service
gateway-service
intake-service
biometric-service
report-service
notification-service
```

Docker 이미지 빌드 예시:

```bash
docker build -t <docker-namespace>/<image-name>:<image-tag> -f services/<service-name>/Dockerfile .
```

### Frontend Web

```bash
cd FE/web
npm ci
npm run build
```

빌드 결과물:

```text
FE/web/dist
```

### Mobile APK

```bash
cd FE/mobile-app
./gradlew :app:assembleDebug --no-daemon -PWEB_APP_BASE_URL=<web-url> -PAPI_BASE_URL=<api-url> -PDIARY_ANALYSIS_API_URL=<diary-analysis-api-url>
```

빌드 결과물:

```text
FE/mobile-app/app/build/outputs/apk/debug/*.apk
```

### AI Service

```bash
docker build -f AI/bio-ml-service/Dockerfile AI/bio-ml-service
```

## 4. 배포 특이사항

- Backend 이미지는 GitLab CI에서 Docker Hub로 push한다.
- Docker image tag는 `$CI_COMMIT_SHORT_SHA`와 `latest`를 함께 사용한다.
- ArgoCD는 `Infra/eks/k8s` 경로의 Kubernetes manifest를 EKS에 sync한다.
- ArgoCD Image Updater는 Docker Hub의 새 이미지 tag를 감지해 배포를 갱신한다.
- Frontend Web은 `FE/web/dist`를 S3에 업로드한 뒤 CloudFront invalidation을 실행한다.
- Backend API 도메인은 `https://api.rebloom.cloud`이다.
- Frontend 도메인은 `https://rebloom.cloud`이다.
- Kubernetes Secret은 Git에 올리지 않고 수동 생성 또는 CI/운영 환경에서 관리한다.
- PostgreSQL, Redis, Kafka, MQTT는 EKS 내부가 아니라 SSAFY 서버 리소스를 사용한다.

## 7. 주요 배포 명령어

### Backend Docker 이미지 빌드 및 push

```bash
cd BE
./gradlew :services:<service-name>:bootJar -x test
docker build -t <docker-namespace>/<image-name>:<image-tag> -t <docker-namespace>/<image-name>:latest -f services/<service-name>/Dockerfile .
docker push <docker-namespace>/<image-name>:<image-tag>
docker push <docker-namespace>/<image-name>:latest
```

### EKS manifest 수동 반영

```bash
kubectl apply -f Infra/eks/k8s
```

### ArgoCD Application 확인

```bash
kubectl get application rebloom -n argocd
```

### 서비스 Pod 확인

```bash
kubectl get pods -n rebloom
```

### 전체 서비스 재시작

```bash
kubectl rollout restart deployment -n rebloom
```
